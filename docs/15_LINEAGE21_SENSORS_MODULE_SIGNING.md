# DOC_212 — 传感器（sensorhub）卡在模块签名：能改 CRC 但无法重新签名 (2026-10-02)

## 1. 现状
- `dumpsys sensorservice`: "No Sensors on the device"。
- 原因链：vendor 里的 sensors HAL 的 rc 与 vintf 声明早已删除（DOC_199，为了让 system_server 不被卡死）；
  更底层：`sensorhub.ko`（donor iPlay50/G1 Max 版）在 L27 内核上加载失败。

## 2. 精确失败原因（实机 insmod + dmesg）
```
sensorhub: disagrees about version of symbol sbuf_set_no_need_wake_lock / sbuf_write / sbuf_read
```
只有这 3 个符号不匹配。L27 内核 `sipc_core` 导出这三个符号的 CRC 都是 **0x0**（`__crc_*` 绝对符号，且 L27 自己的
`sbuf_bridge.ko`/`spipe.ko` 导入的也是 0），donor 期望 `0xd50b468c / 0xcaf2bb8b / 0xf8834763`。
符号本身在 L27 内核里存在（`__ksymtab_sbuf_*` in `[sipc_core]`）。

## 3. 试过的绕过（全部被内核拒绝）
| 做法 | 结果 |
|---|---|
| 把 `__versions` 里这 3 个 CRC 改成 0（`patch_sensorhub.py`） | `Key was rejected by service`：模块签名校验失败（内容变了） |
| 同时去掉签名块（`strip_sig.py`） | `Loading of unsigned module is rejected`（内核强制模块签名） |
| 自己手写 aarch64 ELF 调 `finit_module(fd,"",MODULE_INIT_IGNORE_MODVERSIONS)` 保留原签名（`mk_finit.py`） | 同样 `Loading of unsigned module is rejected`：带 IGNORE_* 标志时内核跳过签名校验，在强制模式下等于无签名 |

结论：**L27 内核强制模块签名**（`CONFIG_MODULE_SIG_FORCE` 一类）。签名密钥是编译时自动生成的
"Build time autogenerated kernel key"，donor 与 L27 模块用的是同一把（serial 相同），但私钥不在我们手里（网上也不会有）。
没有私钥就无法给改过 CRC 的模块重新签名；改内核/cmdline 需要重做 boot，风险高，不做。

## 4. 能解开的前提（任选其一）
1. 拿到 **L27 原厂 vendor_dlkm**（里面的 `sensorhub.ko` 与内核同签名同 CRC，直接可用）。需要 L27 原厂刷机包/整机 super 备份；目前只有 `backup_l27_new_stock`（无 super）。
2. 拿到 L27 内核源码+签名私钥重新编译模块（基本不现实）。

## 5. 附带结论
- 同一问题影响所有"L27 内核没有同名原生模块"的 donor 模块（WiFi/BT 目前可用是因为已有可加载的版本）。
- 之后凡是需要改 donor `.ko`，一律先确认能否保持签名不变；改了就一定加载失败。
- 未验证项：L27 机身上到底有哪些传感器、CM4 sensorhub 固件是否在运行（`vendor.modem.sp-boot=1` 已置位，但没有 sensorhub 的 smsg 通道日志）。
- 手机上已无残留（`/data/local/tmp` 里有测试文件，不影响系统）。
